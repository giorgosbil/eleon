# One-time operator setup: Microsoft Outlook

This is deployment documentation, never customer onboarding. Register **one** product-owned application for all customers. No customer creates an app or supplies credentials.

## Entra portal bootstrap

Azure CLI is unavailable in the implementation environment; no CLI automation or automatic admin-consent grant was added.

1. The product operator signs in to [Microsoft Entra admin center](https://entra.microsoft.com/) in the product's home directory. Open **Entra ID → App registrations → New registration**.
2. Name: **Email Case Workspace**. Supported account types: **Accounts in any organizational directory (Any Microsoft Entra ID tenant — Multitenant)**. The manifest `signInAudience` must be `AzureADMultipleOrgs`. Do not enable personal Microsoft accounts.
3. Add a **Web** redirect URI, exactly `https://example.com/other_things/web/oauth/callback.php` for this development deployment. Register production's own HTTPS callback separately, preferably with a separate environment credential/app. Configure each deployment with its own URI; the application never derives it from request headers. Leave implicit grants and public-client flows disabled.
4. Open **API permissions → Add a permission → Microsoft Graph → Delegated permissions**. Add **User.Read**, **Mail.ReadWrite**, **Mail.Send**, **openid**, **profile**, **offline_access**. Remove unrelated default permissions if present. Do not add application permissions.
5. Under **Certificates & secrets → Client secrets → New client secret**, create a development credential with a short expiry. Copy its **Value** directly into the deployment's secret store; the secret ID is not the credential. Never put the value in git, a ticket, shell history, screenshots, or logs.
6. Copy **Overview → Application (client) ID** into deployment configuration. No customer tenant ID is needed. Existing `tenant_id` settings no longer restrict the product authorization flow.
7. Set the product's verified publisher, branding, support contact, privacy and terms URLs as appropriate before customer rollout. Customer tenant policies may require publisher verification and administrator approval.
8. Admin consent is an explicit action by an authorized Microsoft administrator, subject to that organization's policy. Do not grant tenant-wide consent automatically. A grant in the product's home directory does not approve the app in customer directories.

## Trusted server configuration

Provision these values to both PHP-FPM and the sync worker environment using your deployment secret manager:

```text
ECW_GRAPH_CLIENT_ID=<application-client-id>
ECW_GRAPH_CLIENT_SECRET=<credential-value>
ECW_GRAPH_REDIRECT_URI=<registered-https-callback-uri>
```

Environment configuration takes precedence when `ECW_GRAPH_CLIENT_ID` is present. This permits setup without modifying any host-application files. Alternatively, the existing untracked, protected server `config.local.php` may supply:

```php
'ecw_graph' => [
    'client_id' => '<application-client-id>',
    'client_secret' => '<credential-value>',
    'redirect_uri' => '<registered-https-callback-uri>',
],
```

No configuration or secret was generated by this change. The existing database configuration and 32-byte encryption key must remain available to the web runtime and workers. Restrict config access to those service accounts. Use secure secret management with audited access and rotation for production. Certificate-based client assertions are a stronger future credential option; this implementation currently uses a client secret and does not implement certificate assertions. Rotate credentials before expiry and retain the encryption key while any stored tokens remain encrypted with it.

Configure the web server to omit/redact query strings for OAuth callback access logs and disable credential/body capture in proxies and APM. Microsoft sends short-lived authorization codes in that callback URL. Application error logs intentionally omit provider descriptions and token response contents.

## Database and background workers

From `other_things/`, run as the application's service account:

```sh
php bin/migrate.php --status
php bin/migrate.php
```

The existing Step 02 schema already contains `provider_tenant_id` and the token/status columns. No Step 04B schema migration is needed. Configure a supervised worker or scheduled jobs using absolute deployment paths:

```cron
* * * * * cd /path/to/other_things && php bin/sync_worker.php --max-jobs=50
*/2 * * * * cd /path/to/other_things && php bin/sync_cron.php
```

Do not expose these commands as user onboarding. OAuth queues discovery; a running worker is required for messages to appear. Discovery selects Inbox and Sent and enqueues the existing initial import/delta jobs. Optional webhook setup remains in `docs/SETUP.md`.

## Browser acceptance check

1. Sign into Email Case Workspace → **Settings → Mailbox → Connect Microsoft Outlook**.
2. Sign into Microsoft with a licensed Microsoft 365 mailbox. Consent or use Microsoft's tenant-specific approval workflow.
3. Return to Settings: connected address, background sync state, and last sync. Verify Inbox and Sent begin filling while away from Settings.
4. Repeat under a different application organization with a user from a second Microsoft 365 tenant. Confirm its own consent policy applies and neither application organization sees the other's mailbox/messages.
5. Test denial, required administrator approval, expired/revoked refresh credentials, Sync now, confirmation/cancel of disconnect, and reconnect to the same account. Historical email and Cases must remain.

Administrator approval errors show a fixed explanation, Request administrator approval, and Try again. Request approval opens Microsoft's organizational v2 admin-consent screen (it does not send an email). An administrator must sign in and explicitly approve. If Microsoft offers a tenant's admin-consent request workflow during ordinary sign-in, users can submit that request there. The admin-consent callback never creates a mailbox or proves approval; the user must complete normal authorization afterwards.
